# Contributing to Legibility Office OS

Thank you for your interest in contributing to **Legibility Office OS**.

Legibility Office OS is an open-source Institutional Operating System (IOS) that develops practical frameworks for governance, procurement, Digital Public Infrastructure (DPI), institutional capability, and national competitiveness.

Our goal is not simply to publish documents.

Our goal is to build the world's most trusted open institutional architecture for governments, development finance institutions, researchers, policymakers, and practitioners.

---

# Our Mission

Technology creates potential.

Institutions convert potential into productivity.

Projects do not compete.

Institutional operating systems compete.

Every contribution should make institutions more understandable, more executable, and more resilient.

---

# Guiding Principles

All contributions should align with the following principles:

* Institutional clarity over complexity.
* Systems thinking over isolated interventions.
* Evidence over opinion.
* Execution over aspiration.
* Governance before technology.
* Long-term capability over short-term optimization.
* Open knowledge that strengthens public institutions.

# Contribution Workflow

1. Fork the repository.

2. Create a feature branch.

```
feature/procurement-framework

feature/dpi-reference

feature/governance-model
```

3. Make your changes.

4. Submit a Pull Request.

---

# Commit Convention

Please use Conventional Commits.

Examples:

```
docs: improve governance documentation

feat: add procurement maturity framework

feat: introduce Digital Public Infrastructure schema

fix: correct institutional capability model

refactor: reorganize governance framework

chore: update references
```

---

# Pull Request Guidelines

Every Pull Request should explain:

* Problem addressed
* Why it matters
* Institutional implications
* References (if applicable)

---

# Documentation Standards

Documentation should be:

* Clear
* Evidence-based
* Practical
* Vendor-neutral
* Technology-agnostic where possible

Avoid:

* Marketing language
* Political advocacy
* Product promotion
* Unsupported claims

---

# Diagrams

All diagrams should follow the Legibility Office design language:

* Clean architecture
* Institutional layers
* Minimalist
* White background
* Publication quality

Preferred formats:

* SVG
* PNG
* Mermaid
* Draw.io

---

# Framework Design Standards

Every framework should include:

* Purpose
* Context
* Components
* Operating Principles
* Governance Implications
* Implementation Guidance
* References

---

# Research Standards

Research contributions should:

* Cite credible sources
* Distinguish evidence from interpretation
* Use consistent terminology
* Be reproducible where possible

Preferred citation styles:

* APA
* Chicago
* Harvard

---

# Code Standards

Where software components exist:

* Document APIs
* Write readable code
* Include comments
* Include examples
* Include tests where appropriate
